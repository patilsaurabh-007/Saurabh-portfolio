Project Deep Dive

CampusPay Architecture & Overview

📌 Executive Summary

CampusPay is a purpose-built digital transaction and payment handling system tailored for educational institutions. Traditional campus payments (canteens, libraries, stationery stores, fines) are often fragmented and rely heavily on cash or inconsistent logs. CampusPay centralizes and streamlines this into an integrated digital ledger system.

🗄️ Relational Database Schema Design (SQL)

The core backbone of CampusPay relies on structured relational tables ensuring ACID compliance and ledger consistency:

-- Core Schema Architecture
CREATE TABLE users (
    user_id VARCHAR(20) PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    role ENUM('STUDENT', 'FACULTY', 'VENDOR', 'ADMIN'),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE accounts (
    account_id INT AUTO_INCREMENT PRIMARY KEY,
    user_id VARCHAR(20),
    balance DECIMAL(10, 2) DEFAULT 0.00,
    status ENUM('ACTIVE', 'FROZEN'),
    FOREIGN KEY (user_id) REFERENCES users(user_id)
);

CREATE TABLE transactions (
    txn_id VARCHAR(36) PRIMARY KEY,
    sender_account_id INT,
    receiver_account_id INT,
    amount DECIMAL(10, 2) NOT NULL,
    category ENUM('CAFETERIA', 'LIBRARY', 'FEES', 'TOPUP'),
    status ENUM('PENDING', 'COMPLETED', 'FAILED'),
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (sender_account_id) REFERENCES accounts(account_id),
    FOREIGN KEY (receiver_account_id) REFERENCES accounts(account_id)
);

🎨 User Interface & Experience (HTML5 & CSS3)

  • Responsive Layouts: Flexbox and Grid layouts optimized for student smartphones and campus vendor terminals.
  • Clear Ledger Visuals: Real-time visual feedback for transaction status (Success, Pending, Reversed) with color-coded badges.
  • Intuitive Navigation: Clear flow designed specifically to reduce queue times during peak campus hours.

⚙️ Engineering Highlights & SDLC Process

  • Followed structured SDLC from initial requirements gathering to normalization (3NF) and UI prototyping.
  • Employed Git version control for feature isolation and change tracking.
  • Designed with modular scalability in mind to support future NFC/RFID or QR payment gateways.
